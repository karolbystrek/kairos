KAIROS PRIVATE STAGING RUNBOOK

This runbook is only for disposable, synthetic staging behind Cloudflare
Access. Read docs/REQUIREMENTS.md before any public deployment.

PREPARE

1. Ensure /srv/kairos exists and is writable by the deployment user. From the
   checkout, create .env and the complete staging-only application key set:

   ./setup.sh \
     --non-interactive \
     --replace-env \
     --secrets-directory /srv/kairos/application-secrets \
     --no-tls

   The non-interactive command fails if application keys already exist unless
   --replace-keys or --keep-keys is explicit. It creates the secrets directory
   with mode 0700 and every application key with mode 0400. It never generates
   staging key material in the checkout or an application image.

   Configure every value in .env. Set:

   COMPOSE_FILE=compose.yaml:compose.deployment.yaml
   KAIROS_IMAGE_REGISTRY=ghcr.io/karolbystrek/kairos
   KAIROS_RELEASE_VERSION=sha-<full-source-revision>

   Set matching NEXT_PUBLIC_API_BASE_URL and NEXT_PUBLIC_CUSTOMER_APP_URL
   GitHub variables before publishing the release.

   Set KAIROS_APPLICATION_SECRETS_DIRECTORY to that absolute directory. Compose
   mounts these files read-only at /run/secrets:

   jwt-private.pem
   jwt-public.pem
   webhook-encryption.bin
   vapid-private.pem
   vapid-public.pem
   push-subscription-encryption.bin

   Keep the host directory, files, and .env owned by the deployment user. The
   generated .env has mode 0600.

2. Copy deployment/cloudflared/config.yml.example outside the checkout.
   Replace the UUID and hostnames, keep the final http_status:404 rule, and
   mount the real credential separately. Keep both files root:65532 mode 0440.
   Do not commit environment values or credentials.

3. Validate the configuration:

   docker compose config --quiet
   docker compose run --rm --no-deps cloudflared \
     --config /etc/cloudflared/config.yml tunnel ingress validate

SELECT A RELEASE

Use one successful manually dispatched main CI run. All three images must use
the same sha-<full-source-revision> tag and report linux/amd64. Authenticate to
private packages with docker login ghcr.io using a classic read:packages PAT.

Record the output below in a deployment-user-owned file with mode 0440:

   for service in customer-app panel-app api; do
     docker buildx imagetools inspect \
       "ghcr.io/karolbystrek/kairos/${service}:sha-<full-source-revision>"
   done

Do not deploy a partial set or a tag whose recorded digest changed.

DEPLOY OR REDEPLOY

   docker compose pull customer-app panel-app api
   docker compose up -d --wait --wait-timeout 180 postgres redis
   docker compose up -d --no-deps --wait --wait-timeout 300 api
   docker compose up -d --wait --wait-timeout 180

The API applies Flyway migrations first. If it fails, inspect
docker compose logs api and stop.

Verify health:

   docker compose ps
   docker compose exec -T api \
     wget -q -O - http://127.0.0.1:8080/api/actuator/health
   docker compose exec -T nginx \
     wget -q -O - http://127.0.0.1:8080/health
   docker compose logs --since 10m --tail 200

Verify the customer, panel, and API origins through an Access-authenticated
browser.

ROLLBACK AND RESET

For application rollback, restore the previous recorded release tag and repeat
the deployment. If its API is incompatible with an applied Flyway migration,
use a forward fix or reset staging.

To reset, confirm docker compose config --volumes lists only pgdata, then run:

   docker compose down -v --remove-orphans

Keep the complete key set or replace it with the database. Do not use reset.sh
on the VPS. To replace both, remove the Compose volumes as above and run:

   ./setup.sh \
     --non-interactive \
     --keep-env \
     --secrets-directory /srv/kairos/application-secrets \
     --replace-keys \
     --no-tls

OPERATIONS

   df -h
   docker system df
   docker compose ps
   docker compose logs --since 24h --tail 500
   docker version

Logs are bounded to three 10 MiB files per container. Apply OS and Docker
security updates regularly and update infrastructure images only through
reviewed Compose changes.
